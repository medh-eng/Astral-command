# Aetherfront: Astral Command

A hidden-rank tactical duel for **two commanders on one device**, or **against the Astral AI**.
Twelve pieces each, ten hidden ranks, one Nexus Core. You never see what you are attacking
until you commit — so the game is won with inference, probing and tempo, not luck.

Built as a dependency-free static web app: no build step to run it, no server, no accounts,
no tracking. Open `index.html` and play.

---

## Play it

**Hosted (GitHub Pages):** <https://medh-eng.github.io/Astral-command/> — the design studio for the
next chapter lives at `/docs/vyuha-design-studio.html`.

**Locally, with the source:**

```bash
# any static server works
python3 -m http.server 8080
# → http://localhost:8080
```

**Single file, no server at all:** open `aetherfront-standalone.html` by double-clicking it.
That file is generated by `node tools/build-standalone.mjs` and contains the entire game
(CSS, JS, icons) inline — handy for email, a USB stick, or a tablet with no network.

On iOS/Android you can also "Add to Home Screen": the app ships a web manifest and a service
worker, so it installs and runs offline.

## What is in this build

### Core game
- **12-piece army, 10 hidden ranks** — Senapati, Maharathi, Ashvarohi, Dhanurdhar, Divyadrishti,
  two Yantrik, two Rath, Chara, Shataghni, Durg (the sci-fi names are kept as aliases in the Codex).
- **Three boards** — Small Arena (6×8) and Large Expanse (8×10) with impassable Astral Rifts, plus
  **Chakravyuha**, a wheel of 37 cells (hub + 3 rings × 12 spokes) where the inner rings turn.
- **Abhimanyu** — a scenario on the wheel: eight raiders with no fort of their own must break a
  ten-piece defence and take its fort before round 24. Take the fort and the breach succeeds; lose
  every raider, or run out of rounds, and the wheel closes.
- **The chakra turns** — on the wheel, rings 1 and 2 rotate one spoke clockwise every fifth round,
  carrying whatever stands on them and revealing it. The hub touches all twelve spokes and exposes
  whoever stands on it. Arcs are one cell at a time; only the spokes are long lanes.
- **Three special powers** — Psionic Scan (Seer), Arc Barrage (Lancer), Phase Dash (Valkyrie).
- **Two tie rules** — Attacker Advantage with Shield Break, or classic Mutual Destruction.
- **Anti-stall** — the two-square rule is enforced on every move, and 60 orders without a
  capture ends the match as a draw (countdown shown in the intel panel).
- **Win conditions** — capture the Nexus Core (melee or barrage), or leave the opponent with no legal action.

### New in this version
| Area | What it does |
| --- | --- |
| **Commander profiles / login** | Local profiles with sigil avatars and an optional 4–8 digit access code, stretched with PBKDF2-SHA256 (120k iterations) via Web Crypto. Guest mode for zero friction. Per-profile service record: wins, losses, streaks, captures, rank badge. |
| **Saved games** | One rolling autosave plus three manual slots, each with a live board thumbnail. Load, overwrite, rename or delete. Export/import the whole database as JSON to move between devices. |
| **Sound** | A full synthesised score and SFX suite generated live with the Web Audio API — no audio files, no downloads. Separate sliders for effects and music, mute, haptics. |
| **Graphics** | Hand-drawn SVG emblems for all ten unit classes, animated rift tiles, FLIP piece-movement animation, particle bursts and floating combat text on a dedicated canvas, screen shake, glass UI. |
| **Intel ledger** | Live belief model in the side panel: which enemy pieces are still unaccounted for, which are identified, which are destroyed, and what the enemy knows about you. |
| **Clash odds** | Before you strike an unknown piece, you get the real probability of winning, losing, trading, or hitting the Core — averaged over every rank the enemy could still be hiding. |
| **Advisor** | Ask for the three best orders, scored by the same belief model the AI uses. Click one to preview it on the board. Also plays your move automatically if the turn clock runs out. |
| **Scenarios** | Asymmetric setups on the same rules: per-side rosters, a round limit, and win conditions that are not just "take the fort". |
| **Three AI tiers** | Recruit (greedy, noisy), Veteran (beliefs + reply check), Archon (full belief model with 1-ply lookahead). |
| **Pass & play privacy curtain** | Between deployments and between turns, a full-screen curtain hides the board while the device changes hands. |
| **Turn clock** | Off, 60s or 30s per turn, with a warning pulse and an auto-move fallback. |
| **Cell-graph engine** | The board is a graph of cells with neighbours and rays, not a grid — the same rules code drives squares, the wheel, and any future hex or triangle board. |
| **Accessibility** | Colour-blind palette (blue/orange), high contrast, reduced motion, keyboard play on the board (arrows + Enter), ARIA labels on every square, visible focus rings. |
| **Installable / offline** | Web manifest + service worker cache of the whole shell. |

## How to play in one screen

1. **Deploy** — twelve pieces anywhere in your back three rows. Tap two squares to swap.
   Citadel / Blitz / Lattice / Shuffle presets, or save your own formation for later.
2. **Move or strike** — tap your piece, then tap a highlighted square. Everything moves
   orthogonally. Rifts block movement (not the Lancer's shot).
3. **Use powers** — select the Seer, Lancer or Valkyrie and switch the ability bar to
   Scan / Barrage. Scanning is free information; a barrage is a free probe at range.
4. **Read the intel** — pieces that have never moved can still be a Mine or the Core. The
   intel panel turns that single fact into odds.
5. **Break the core** — capture the enemy Nexus Core, or leave them with no legal move.

Full rules, every rank and every edge case live in the in-game **Codex** (top bar → book icon).

## Project layout

```
index.html                  app shell (screens, HUD, board containers)
css/app.css                 design system: glass panels, board, tokens, modals, responsive
js/units.js                 roster, boards, difficulties — the balance file
js/geometry.js              board geometry: cells, neighbours, rays, zones, distances
js/engine.js                pure rules engine (no DOM): legality, combat, turns, beliefs, rotation
js/ai.js                    belief-model bot + advisor
js/audio.js                 Web Audio SFX + procedural score
js/storage.js               profiles, PIN hashing, saves, settings, export/import
js/art.js                   inline SVG emblems, sigils, icons, board thumbnails
js/fx.js                    particle canvas, floating text, shake, toasts
js/ui.js                    screens, auth, home, setup, modals, codex, saves, settings
js/game.js                  battle screen: board render, input, AI loop, curtains, results
js/main.js                  boot
sw.js, manifest.webmanifest offline install
assets/icon.svg             app icon
tests/                      headless rule + self-play + DOM tests
tools/                      standalone build, screenshot harness
aetherfront-standalone.html generated single-file build
```

The engine is deliberately DOM-free, so the rules can be tested and simulated in Node:

```bash
node tests/rules.mjs        # 60 rule assertions (combat, traps, rifts, rotation, hub, beliefs)
node tests/selfplay.mjs 60  # 60 full AI-vs-AI matches across all three boards
node tests/ui.mjs           # boots index.html in jsdom and drives login → deploy → battle → save
```

`npm install` is only needed for `tests/ui.mjs` (jsdom) and `tools/shots.mjs` (puppeteer-core).

## Tuning the game

Everything you would want to adjust is data, not logic:

- **Ranks, counts, movement, powers** → `js/units.js` (`UNIT_DEFS`, `ROSTER_ORDER`).
  Rank numbers drive combat directly; `moveRange: 99` is the Rath's slide.
- **Boards and rift layouts** → `js/units.js` (`BOARDS`) for labels, `js/geometry.js` for shape.
  Rifts are cell ids (`"row,col"` on squares).
- **The wheel** → `js/geometry.js` (`wheelBoard`: sectors, rings, zones, rotation rings) and
  `js/engine.js` (`rotate`).
- **Scenarios** → `js/units.js` (`SCENARIOS`: rosters per side, allowed boards, turn limit).
  The engine reads `state.rosters` for army sizes and the belief model, and `state.turnLimit`
  for the clock, so a new scenario is data.
- **AI difficulty** → `js/units.js` (`DIFFICULTIES`: `noise`, `think`, `depth`).
- **Starting formations** → `js/engine.js` (`presetSlots`, `PRESET_ORDER`).
- **Combat rules** → `js/engine.js` (`resolveMelee`, `applyAction`).
- **Colours, type, spacing** → `css/app.css` (`:root` variables, plus `html.cb` for colour-blind).

After any change, run `node tests/rules.mjs && node tests/selfplay.mjs 40`, then
`node tools/build-standalone.mjs` to refresh the single-file build.

## Notes on privacy

There is no backend. Profiles, PIN hashes, stats, formations and saved games live in this
browser's `localStorage`. PINs are stretched with PBKDF2-SHA256 where Web Crypto is available
and fall back to a documented iterated hash otherwise — that keeps a sibling out of your saved
games, but it is not a security boundary against someone with the device and dev tools.
Use **Export backup** to move your data between devices.
